# АРР Медиа — новый сайт

Рабочий дизайн-прототип сайта событийного агентства. Здесь находятся интерфейс,
локальные фотографии и шрифты, сравнение дизайна и план подключения CMS.

**Состояние на 25 ноября 2026:** прототип работает; CMS, база данных и публикация
на хостинге ещё не настроены. Следующая задача — первая рабочая публикация проекта
через Payload CMS. Figma не требуется для запуска или продолжения разработки.

## Быстрый старт

Нужны Node.js 22+ и npm (проверено на Node.js 24.12.0). Команды одинаковы для
Windows, macOS и Linux. Выполнять из корня этого проекта, рядом с `package.json`.

```sh
node --version
npm run dev
```

Открыть [сайт](http://127.0.0.1:4178/) и
[сравнение до / после](http://127.0.0.1:4178/comparison.html).
Остановить сервер: `Ctrl+C`. Изменения видны после обновления страницы.
Если порт 4178 занят, остановить ранее запущенный экземпляр.

Сейчас внешних npm-зависимостей нет: `npm install`, база данных, Docker и `.env`
для просмотра не нужны. Все используемые изображения и шрифты уже в проекте.
Открывать `index.html` двойным щелчком нельзя: JS-модулям нужен HTTP-сервер.
Сервер предназначен только для локального просмотра и слушает `127.0.0.1`.

## Продолжить завтра

1. Склонировать будущий репозиторий и перейти в его папку.
2. Запустить `npm run dev`, убедиться, что видны главная и проекты.
3. Прочитать [передачу работы и порядок следующих шагов](docs/NEXT-STEPS.md).
4. Реализовать первый сценарий из [плана CMS](docs/cms-next-steps.md):
   вход → правка проекта и фото → черновик → публикация → изменение на сайте.

## Структура

```text
design-concept/
  index.html                Главная и оболочка страниц проектов
  design.css                Действующие стили
  app.js                    Фильтры, навигация, меню и галереи
  content/projects.js       Пять проектов и три сцены главной
  assets/                   Фото, исходный логотип, шрифты и лицензия
  review/                   Сохранённые снимки до / после
  comparison.html           Визуальный отчёт
  server.mjs                Локальный сервер
  design-handoff.json       Параметры и ограничения дизайна
cms/                        Место для будущего приложения CMS
docs/                       Планы, состояние и исследование
```

`styles.css` — предыдущий вариант стилей, текущая страница его не подключает.
Редактировать нужно `design.css`. Папка `cms` пока содержит только пояснение.

## Принятые решения

- Зарегистрированный логотип `design-concept/assets/arr_logo.svg` не менять:
  сохранить рисунок, цвета и пропорции. Он уже используется в шапке, подвале и favicon.
- Шапка закреплена при прокрутке. Сохранять доступность якорей, клавиатурную
  навигацию и поддержку уменьшения анимации.
- Описания проектов и годы — редакторские черновики для проверки перед публикацией.
- Целевое направление: Next.js + Payload + PostgreSQL; фото в production —
  в объектном хранилище. Сегодня это план, установленных пакетов CMS нет.
- Контент отделять от оформления. Схему CMS преобразовывать в данные витрины
  через адаптер. Подробнее об ограничениях и росте — в плане CMS.

## Проверки

```sh
npm run check
```

Это проверка синтаксиса JavaScript, не полноценные браузерные тесты.
После изменения интерфейса вручную проверить мобильную и широкую версию,
закреплённую шапку, фильтры, открытие проекта и галереи, Escape и мобильное меню.
В предыдущей сессии браузерные проверки прошли на ширинах 320–1920 px.

`design-concept/refinement-checks.js` и `review-checks.js` — сценарии для команды
`run-code --filename` инструмента Playwright CLI. Это не тесты для `node` или
`playwright test`; инструмент и браузер нужно установить отдельно. Новые снимки
пишутся в игнорируемую папку `artifacts/visual-review/` относительно запуска.

## Подключить Git-репозиторий

Корнем репозитория должна стать **эта папка**, а не родительская папка со старым
сайтом. README и планы не зависят от соседних проектов или путей на этом компьютере.
Для пустого удалённого репозитория:

```sh
git init -b main
git add .
git diff --cached --stat
git status
git commit -m "Add ARR Media design prototype and CMS roadmap"
git remote add origin <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

Подставить фактический URL вместо `<URL_ВАШЕГО_РЕПОЗИТОРИЯ>`.
Перед коммитом просмотреть список файлов: `.env`, профили браузеров и локальные
данные не должны попадать в Git. Если удалённый репозиторий уже содержит коммиты,
сначала клонировать его и перенести сюда содержимое проекта; не делать force push.
После добавления зависимостей хранить lockfile выбранного пакетного менеджера в Git.
